# Android Storage Audit V1 — implementation decisions (Supplement §12)

Each decision lists: rationale, trade-off, validation method. These are the explicit choices the build commits to; they are implemented in the code and exercised by tests.

| # | Decision | Rationale | Trade-off / consequence | Validation method |
|---|---|---|---|---|
| 1 | **Python minimum 3.8**, stdlib-only runtime. Bash launcher only. Tested here on CPython 3.13.18. | Termux ships current CPython; stdlib minimizes supply-chain risk and APK size | No syntax newer than 3.8 semantics used intentionally | `python3 -m compileall`, test-suite run, `pyproject.toml` `requires-python = ">=3.8"` |
| 2 | **Root resolution:** `--root` flag > `STORAGE_AUDIT_ROOT` env var > `$HOME/storage/shared`. Canonicalized once with `os.path.realpath`; must exist, be a directory, and be listable. **Never falls back to home/other paths.** | Supplement §3.1: no mislabelled fallback | On non-Termux machines `~/storage/shared` usually does not exist → clear stop with instructions (correct behavior) | `tests/test_safety.py` (root branches), `tests/test_cli.py` (check command, env override) |
| 3 | **Mount-boundary policy (V1):** no intentional crossing of filesystem boundaries. Root's `st_dev` is recorded; any descendant on a different device is recorded as a `skipped` entry (`skip_reason=mount_boundary`) and not descended into. | Supplement §3.2 | Some Android FUSE setups may present everything as one device; where detection is unreliable the limitation is reported, not hidden | Fixture with a simulated different-device entry is not reproducible portably; logic unit-tested via injected device id; documented in LIMITATIONS.md |
| 4 | **Symlinks never followed.** Entries use `lstat`; directory symlinks are recorded, never recursed; loops impossible by construction. `readlink` text stored bounded (≤ 4096 chars) and never resolved; `lexists` used only to flag broken links | Master §3.3/§5.1, Supplement §3.2/§3.3 | Symlinked trees that the user expects to be scanned appear as symlink entries only (by design) | Tests: symlink to file/dir, broken symlink, symlink loop fixture (must terminate), escape-outside-root attempt |
| 5 | **Output default:** `$HOME/.local/share/android-storage-audit/` with `storage_audit.sqlite3`, `reports/`, `logs/`. `--db` / `--output-dir` override. If the output dir resolves inside the scan root it is excluded exactly from traversal (exclusion recorded, warning printed); `output == root` or `root` inside output aborts the run. Output subtree excluded and recorded in `scan_runs.exclusions_json`. | Master §3.3/§10, Supplement §3.2 | Slightly more friction for users who insist on output-in-root; correct default stays outside | Tests: exclusion logic, refusal cases, recorded exclusion |
| 6 | **Status model:** `running`, `completed`, `completed_with_gaps`, `cancelled`, `failed`, `interrupted_or_recovered`. `completed_with_gaps` ⇔ at least one observed error/inaccessible/skipped entry (and `coverage_incomplete=1`). No partial report may look complete. | Supplement §2.1 — pick one model, use everywhere | Two "success-like" statuses; mitigated by consistent badge/label everywhere | Tests: status transitions, report badge, exports/manifest status, cancelled ≠ complete |
| 7 | **Required vs optional metadata:** required = run id, relative path, absolute path, name, kind, depth. Required-for-files = size when observable; `size_status` says `observed`/`unavailable`/`failed`/`not_applicable`. birthtime optional; `ctime` is never labelled creation time. | Supplement §2.4, §4.2 | Slightly wider schema | Schema tests, reconciling analytics |
| 8 | **File count when stat fails:** entry is recorded with `stat_status='failed'`, counted in `files_seen`/`errors`, **not** in `files_recorded` or bytes totals. Never counted as zero bytes. | Supplement §2.4, §9 definitions |  | Fixture: file removed mid-scan; DB assertions |
| 9 | **Directory aggregation:** bottom-up accumulation over persisted entries, depth-descending; recursive counts/bytes stored in `directory_stats`. Grand total = Σ regular-file sizes, computed once, never by summing directory rollups (no double counting). Directory `st_size` never reported as content size. | Master §5.3/§5.5, Supplement §3.5 | One extra pass over directories (fast; indexed) | Analytics tests: nested totals, overlap test, top-N |
| 10 | **Classification:** single central map in `classifier.py` (`CLASSIFICATION_VERSION = "1.0.0"`), recorded per entry and in each run. Extension match case-insensitive on lowercased suffix; original spelling preserved. Dotfiles (leading `.`, no other dot) ⇒ no extension. `archive.tar.gz` ⇒ compound `tar.gz`. Unknown ⇒ `unknown` category + NULL MIME. MIME from `mimetypes` is advisory and labelled filename-derived. | Master §5.4, Supplement §3.4 | Rare extensions stay `unknown` by design | Classifier tests: full group coverage, dotfiles, compound, uppercase, unknown, misleading extensions |
| 11 | **Time convention:** raw epoch stored everywhere; display = local time with explicit UTC offset (`datetime.fromtimestamp(ts).astimezone().isoformat(sep=' ', timespec='seconds')`); report header shows timezone of the generating host and that it is host-local. Unavailable ⇒ “Unavailable”, never epoch 0. | Supplement §3.5 | Cross-device report comparisons show host TZ | Exporter tests, report assertions |
| 12 | **Schema:** `SCHEMA_VERSION = 1`, `schema_migrations` table + `PRAGMA user_version`; forward-only migrations. V1 ships migration 001. Fresh DBs get the full schema; an older `user_version` DB runs migrations (tested via synthetic v0/v1 fixture DB). | Master §6, Supplement §3.6 | Migration framework minimal by design | Migration test builds an old-version DB and migrates |
| 13 | **Batching & durability:** `PRAGMA foreign_keys=ON`, `journal_mode=WAL`, `synchronous=FULL`, batch commit every 500 entries (default; `--batch-size` 50–5000). No per-file transactions; no unsafe durability shortcuts. | Master §5.6, Supplement §3.6, §11 | Slightly slower than NORMAL sync; correct by default | Tests run with real commits; integrity_check in tests; batch boundaries exercised |
| 14 | **Cancellation/recovery:** SIGINT/SIGTERM set a cancel flag; traversal stops scheduling new directories; current batch commits; run marked `cancelled` (exit 3). On startup the tool inspects `running` rows: if stored PID is not alive (`os.kill(pid, 0)` → `ESRCH`) → `interrupted_or_recovered` (exit 4 for `check`/warn otherwise); if alive → warn “another scan may be running”; if undeterminable → leave as-is with explicit warning. No auto-resume in V1 (stated plainly). | Master §5.6, Supplement §2.1/§3.7 | No resume; rerun required | Signal tests (subprocess scan interrupted), stale-run recovery test |
| 15 | **Report pagination:** `files_page_N.html` static pages, 500 rows/page, prev/next + “Page N of M”. Full-inventory search page embeds data inline when ≤ 30,000 entries; otherwise emits `data/inventory_NNN.js` chunks loaded with classic `<script src>` (works under `file://`, unlike fetch/XHR) ≤ ~4,000 records per chunk, search page states chunked mode. Directory Explorer: nested `<details>` tree for ≤ 30,000 directories, else paginated directory table. Nothing multi-hundred-MB; every record remains available. | Master §7.3, Supplement §2.5/§5.2 | Two code paths for search page; both tested | Report tests: page counts, record conservation, boundary pages, offline check |
| 16 | **CSV formula-injection safety:** any cell whose first character ∈ {`=`, `+`, `-`, `@`} or ∈ {TAB, CR} is prefixed with `'`; documented in export README and methodology; database stores raw value untouched; JSONL carries raw value. | Master §10, Supplement §6.1 | CSV consumers see `'` prefix on hostile cells (standard mitigation) | Exporter tests with hostile filenames |
| 17 | **JSON/JSONL:** `schema_version: 1`, UTF-8, one object per line, `null` for unavailable, no NaN/Infinity (sanitizer rejects), manifest envelope in `manifest.json`. | Supplement §6.2 | — | Parse-back tests |
| 18 | **Tree chunking:** `directory_tree.txt` written fully; if it exceeds 8 MiB or 250,000 lines it is split into `directory_tree_part_NNN.txt` (≤ 8 MiB each, line-aligned) plus `directory_tree_index.txt` (chunk list, line ranges, totals). Index states total chunk count. Never labelled complete when truncated (no truncation mode exists). | Supplement §6.3 | Two files in worst case | Tree tests with small injected limits |
| 19 | **Offline verification:** automated test scans generated report tree for `http://`, `https://`, `//cdn`, `url(http`, external `<script src=>`/`<link href=>`; `node --check` on `report.js`; HTML parses via stdlib `html.parser`; all intra-report links resolve to emitted files. | Master §7.4/§11.3, Supplement §5.5 | None | `tests/test_report.py::TestOfflineNoNetworkAssets`, link-check test |
| 20 | **Privacy/logging:** rotating file log (1 MiB × 2) under output dir; INFO default; full paths only with `--verbose`; URLs/hosts never logged; no telemetry, no network. Report carries privacy notice; README/guide repeat the warning. No identifiers beyond optional device `st_dev`/inode (never serial/IMEI/Android ID — environment_json excludes them). | Master §10, Supplement §5.5/§10 | Less convenient debugging without `--verbose`; by design | Log inspection test; environment_json key audit test |
| 21 | **Fixtures & thresholds:** all fixtures synthetic and labelled; suite must be 100% pass for V1 completion claim; permission tests skip gracefully when running as root (root bypasses permission bits — documented, mocked where unreliable). | Master §11, Supplement §7 | Some POSIX edge cases untestable as root | CI evidence in `docs/TEST_EVIDENCE.md` |
| 22 | **Validation boundary:** all green evidence in this delivery was produced in the Arena Linux container, never on the user's phone. On-device validation is a required user step; see `docs/ANDROID_TERMUX_GUIDE.md`. | Master §0/§14, Supplement §8 Gate A/G | Fewer real-world guarantees until first phone run | Explicit wording in all docs; no phone claims anywhere |
